# Signal — Build Context (locked standing rules)

This file records standing instructions from the user that must hold for the entire build. Re-read it alongside `build-prompts.md`, `crm-spec.md`, and `signal-design.md` before every phase and at regular checkpoints during work — the build can't be production-grade unless everything in the PRD works, and context drift is the main way that fails.

## Standing rules (locked by the user, 2026-08-14)

1. **`signal-crm` is the ONLY project.** The old `Signal` folder in the original workspace is out of scope entirely — do not read it, copy from it, or let its contents influence this build.
2. **Re-read the docs regularly.** Before every phase, and at checkpoints during a phase: re-read `build-prompts.md` (phase scope + stop conditions), `crm-spec.md` (the PRD — canonical source), and `signal-design.md` (design system — source of truth for frontend work). If the design doc and PRD ever look out of sync, flag it rather than guessing.
3. **Phase discipline.** Run phases in order, one at a time. Each phase ends at its STOP CONDITION with a report; wait for sign-off before the next phase. No scope creep into the next phase, no "just keep going."
4. **Credentials.** Every credential block in the build prompts: present the exact numbered steps to the user and WAIT for real values. Never proceed with a placeholder/fake key. Never switch to live/production keys without explicit user confirmation.
5. **Schema and money rules are locked.** Section 18 schema must match exactly (flag deviations, don't silently fix). Money fields are integers in minor units. `writeTimelineEvent()` is the only write path to `timeline_events`.

## Design decision — accent color (locked by the user, 2026-08-14)

The accent color is **black `#1E1E1E`**, not indigo. This overrides the `--beacon` value and all "violet/indigo" wording in both docs (already updated in `crm-spec.md` §22 and `signal-design.md` §1). The `--beacon` semantics stay the same — it is still the single accent reserved exclusively for things needing the freelancer's attention or action.

## Modal surfaces focus audit (ContactForm / InvoiceForm / ConfirmDialog / UserMenu) — 2 real bugs fixed
Audited every modal surface for the palette-class focus/aria gaps. ContactForm, InvoiceForm, ConfirmDialog, MergeDialog, ImportRepoDialog, ProjectForm, PortalLinkButton, settings modals ALL go through the shared ui/Modal.tsx, which already had aria-modal, Tab trap, Esc close, focus restore, and body scroll-lock. ## Palette fuzzy search — done
Replaced substring-only palette matching with a scored fuzzy search:
- New `src/lib/fuzzy.ts` — pure, dependency-free `fuzzyScore(query, text)` (subsequence DP with per-typo-count states) + `bestFieldScore` for multi-field rows.
- **Typo tolerance, keyboard-aware**: a substitution is only accepted when the pair is QWERTY-adjacent (m↔n so "acne"→"Acme"; arbitrary substitutions rejected so "cma" can't match "Acme" via a→e), plus an adjacent-swap transition ("googel"→"Google"). Budget ~1 typo per 4 query chars.
- **Ranking bonuses**: prefix (+25), word-boundary (+15), contiguity (+10), case-exact (+2); **gap penalty 30/char** is the dominant term — so a tight typo match outranks a long scattered coincidence (fzf's insight). Heavy scattering falls below the MIN_SCORE floor → rejected. Trailing text after the last match is free (best score across end positions).
- CommandPalette: every row scored against label + sub fields, ranked best-first with a stable sort (ties keep data order); actions appended below with their own fuzzy filter. Empty query keeps the old actions-first order.
- Tests: `tests/fuzzy.test.ts` (23 unit tests — basics, ranking, typo tolerance, subsequence, bestFieldScore, realistic scenarios) + a permanent Playwright test proving a typo ("acne") surfaces the seeded Acme client ahead of a scattered "Background Writer" coincidence. The live verification caught the original weighting bug (scattered match outranked the typo match) and the trailing-text penalty bug (short query → null) — both fixed.
Verified: tsc clean, 176/176 vitest, 28/28 Playwright. Live: "acme"/"acm"/"acne"/"zapr" all surface the right clients in the right order.
